# 01. TV Controller QA / Refactoring Report

작성일: 2026-05-19

## 1. 목적

본 문서는 `TDD_TV_11` 프로젝트의 현재 구현과 테스트 상태를 QA/리팩토링 관점에서 정리한 보고서이다.

프로젝트는 리모컨 입력을 받아 TV 채널을 제어하고, 외부 `Tuner` 인터페이스를 통해 채널 변경을 수행하는 C++17 기반 실습 프로젝트이다. Cursor AI 작업 규칙은 프로젝트 루트의 `.cursorrules`에 정의되어 있으며, 핵심 원칙은 기존 인터페이스 보호, 테스트 Green 상태 유지, 작은 단위의 안전한 리팩토링이다.

## 2. 기술 스택

- Language: C++17
- Build: CMake
- Test: Google Test, Google Mock
- Coverage: gcov/lcov 사용 가능

## 3. 프로젝트 구조

- `include/Tuner.h`: 외부 튜너 인터페이스
- `include/TVController.h`: 기존 TV 컨트롤러 클래스
- `include/TVChannelController.h`: 숫자 입력, 선호 채널, 다음 선호 채널 기능 구현
- `include/fakeTuner.h`: 테스트용 Fake Tuner
- `include/remoteKey.h`: 리모컨 키 정의
- `test/TunerTest.cpp`: `Tuner` 인터페이스 Mock 기반 테스트
- `test/TVControllerTest.cpp`: `TVChannelController` 기능 테스트
- `CMakeLists.txt`: Google Test FetchContent 및 테스트 실행 대상 정의

## 5. 현재 구현 기능 요약

### 숫자 버튼 채널 변경

- 한 자리 숫자 입력 후 확인 버튼을 누르면 해당 채널로 변경된다.
- 두 자리 숫자 입력 시 즉시 채널이 변경된다.
- 네 자리 연속 입력은 두 자리 단위로 처리되어 `12`, `34`와 같은 흐름으로 변경된다.
- `0`, `7` 입력 시 채널 `7`로 변경되는 테스트가 존재한다.

### 선호 채널

- 현재 채널을 선호 채널에 추가할 수 있다.
- 이미 선호 채널인 경우 다시 누르면 제거된다.
- 내부 저장소로 `std::set<int>`를 사용해 정렬과 중복 제거를 처리한다.

### 다음 선호 채널

- 현재 채널보다 큰 선호 채널 중 가장 가까운 채널로 이동한다.
- 더 큰 선호 채널이 없으면 가장 작은 선호 채널로 순환한다.
- 선호 채널 목록이 비어 있으면 현재 채널을 유지한다.

## 6. QA 관점 주요 이슈

### 채널 표시 규칙 불일치

`.cursorrules`에 따르면 채널은 `00`부터 `99`까지의 두 자리 값으로 취급해야 한다. 그러나 현재 테스트와 `FakeTuner`는 `"1"`, `"7"`처럼 한 자리 문자열을 반환하는 케이스가 있다.

향후 테스트를 정리할 때 `00`, `01`, `09`, `10`, `99`를 각각 별도 케이스로 검증하는 것이 좋다.

### 세 자리 이상 입력 규칙 불일치

프로젝트 규칙은 세 자리 이상 입력 시 마지막 두 자리가 채널이 되어야 한다고 정의한다. 예를 들어 `123`은 `23`, `100`은 `00`이어야 한다.

현재 `TVChannelController::pressNumber()`는 입력 버퍼 크기가 3 이상이면 버퍼를 비우고 입력을 무효화한다. 이는 현재 규칙과 다르므로, 바로 구현을 수정하기 전에 해당 동작을 명확히 검증하는 테스트를 먼저 추가해야 한다.

### README 요구사항 대비 미구현 영역

README에는 채널 검색 버튼, 채널 업/다운, 검색 결과 기반 업/다운 이동이 포함되어 있다. 현재 구현과 테스트는 숫자 입력, 선호 채널, 다음 선호 채널에 집중되어 있어 README의 전체 요구사항을 모두 커버하지는 않는다.

### 테스트 스타일 개선 필요

`.cursorrules`는 Given-When-Then, `TEST_F`, 채널 1개당 별도 케이스 작성을 요구한다. 현재 테스트는 대부분 `TEST_F`를 사용하지만 Given-When-Then 구분과 채널 케이스 분리는 더 일관되게 개선할 수 있다.

## 7. 리팩토링 제안

테스트 Green 상태를 유지하면서 다음 순서로 진행하는 것을 권장한다.

1. 현재 동작 보호 테스트 보강
   - `00`, `01`, `09`, `10`, `99` 입력을 별도 테스트로 작성한다.
   - 세 자리 이상 입력 시 마지막 두 자리 채널 처리 테스트를 추가한다.

2. 채널 관련 매직 넘버 상수화
   - 최소 채널 `0`
   - 최대 채널 `99`
   - 채널 표시 폭 `2`
   - 숫자 버튼 범위 `0`~`9`

3. 숫자 입력 버퍼 로직 분리
   - 숫자 누적
   - 채널 값 계산
   - 채널 포맷팅
   - 버퍼 초기화

4. README 요구사항 확장 테스트 작성
   - 채널 검색 버튼
   - 검색 결과가 없는 경우의 채널 업/다운
   - 검색 결과가 있는 경우의 채널 업/다운

## 8. 작업 시 절대 준수 사항

- `TVController` 구조는 수정하지 않는다.
- `Tuner` 인터페이스는 수정하지 않는다.
- `remoteKey` 정의는 수정하지 않는다.
- 모든 리팩토링은 테스트가 Green인 상태에서만 진행한다.
- 동작 변경과 리팩토링을 같은 단계에 섞지 않는다.

## 9. 결론

현재 프로젝트는 24개 테스트가 모두 통과하는 안정적인 출발점을 가지고 있다. 다만 `.cursorrules`에 새로 정의된 두 자리 채널 규칙과 세 자리 이상 입력 규칙은 현재 구현과 차이가 있으므로, 다음 단계에서는 먼저 테스트를 통해 기대 동작을 명확히 고정한 뒤 작은 단위로 구현을 개선하는 것이 바람직하다.
